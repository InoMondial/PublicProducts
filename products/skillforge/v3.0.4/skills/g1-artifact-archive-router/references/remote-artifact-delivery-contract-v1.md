# Remote Artifact Persistence & Link Delivery Contract

**Contract ID:** `INC_REMOTE_ARTIFACT_DELIVERY_V1`  
**Owner:** `G1-Artifact Archive Router`  
**Framework:** `SkillForge`

## 1. Rule
A generated document/artifact must not use the user's Windows filesystem, Chat/Agent inline body, or any unmanaged local path as its governed storage/delivery destination.

Required closure:

`generated bytes/content -> G1 class route -> [document-class: SharePoint-only | other governed artifact: GitHub and/or SharePoint] -> remote read-back -> canonical verified link -> user`

A file/document request is not complete merely because content exists in Chat, Agent output, sandbox, Windows, clipboard, terminal output, or an unverified upload response.

## 2. Document-class route

Use `INC_G1_DOCUMENT_CLASS_STORAGE_V1`.

Durable DOC/DOCX, XLS/XLSX/XLSM, PDF, PPT/PPTX and equivalent human/business document/report binaries use governed SharePoint as the only canonical storage authority. Their bytes MUST NOT be stored in current normative/runtime GitHub paths. GitHub may store source/generator code and lightweight SharePoint pointer/provenance metadata that contains no embedded document bytes.

Document-class success requires SharePoint write, remote read-back, content identity/hash/size verification and a verified SharePoint link. Historical Git evidence is preserved; history rewrite or force-purge requires separate explicit owner approval.

## 3. Durable vs temporary
- Durable/source/normative/release/evidence artifacts follow the canonical G1 GitHub/SharePoint route.
- Temporary/draft/ad-hoc/disposable artifacts still require a governed **remote Temporary** location, stable link, and lifecycle/cleanup metadata.
- Temporary classification never authorizes unmanaged Windows/local persistence.

## 4. Technical transient buffers
A connector/tool may require a bounded transient transport buffer. Such a buffer:
- is not a governed artifact authority;
- is not final user delivery;
- must not be treated as a canonical copy;
- exists only as long as technically required for remote transfer/read-back;
- must be deleted or reconciled after verified remote persistence when the tool surface permits it.

This exception is transport plumbing, not permission for Windows/local document storage.

## 5. Chat and Agent behavior
Chat/Agent may summarize, explain, or quote a small portion of an artifact, but must not substitute inline content for the requested file/document. The user receives the verified GitHub/SharePoint link after persistence.

If remote persistence is unavailable, return `REMOTE_ARTIFACT_PERSISTENCE_REQUIRED` or `REMOTE_ARTIFACT_DELIVERY_BLOCKED`; do not claim completion and do not fall back to local-only/manual-upload delivery.

## 6. Temporary remote lifecycle
Temporary remote artifacts record at minimum:
- `artifact_id`
- `transaction_id`
- `classification: TEMPORARY`
- `created_at`
- `cleanup_policy` or `review_after`
- canonical remote location/link
- remote read-back status

G1 decides the physical destination from governed routing; callers cannot invent a temporary SharePoint/GitHub path outside the authorized namespace.

## 7. Verification
Before `SUCCESS_VERIFIED` for a generated artifact:
1. remote object exists;
2. canonical route is valid;
3. read-back succeeds;
4. size/hash or content identity is verified when applicable;
5. returned link resolves to the governed object;
6. no local/Windows copy is treated as authority;
7. temporary objects have cleanup metadata.

## 8. Failures
`WINDOWS_ARTIFACT_DESTINATION_FORBIDDEN | LOCAL_ONLY_DELIVERY_FORBIDDEN | INLINE_ONLY_ARTIFACT_DELIVERY_FORBIDDEN | REMOTE_ARTIFACT_PERSISTENCE_REQUIRED | REMOTE_ARTIFACT_DELIVERY_BLOCKED | TEMPORARY_REMOTE_LIFECYCLE_MISSING | G1_DOCUMENT_CLASS_GITHUB_STORAGE_FORBIDDEN | G1_DOCUMENT_POINTER_SHAREPOINT_REF_REQUIRED | G1_DOCUMENT_POINTER_PROVENANCE_REQUIRED | G1_DOCUMENT_POINTER_EMBEDDED_BYTES_FORBIDDEN`.
